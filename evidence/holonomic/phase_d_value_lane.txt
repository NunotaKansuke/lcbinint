ATPT holonomic solver — Phase D value lane
==========================================
Checkpoint §33.  Date 2026-09-09.  Branch claude/holonomic-solver-m1.

GOAL (user message 29, agenda item 1)
-------------------------------------
Production kValue (FiniteSourceMethod::holonomic_binary = 6) today runs the
fused epoch_jacobian / epoch_jacobian_prepared pass and THROWS AWAY the
Jacobian.  §29 measured ~1 ms/epoch of that ~2.2 ms end-to-end going to
unused derivative assembly.  Task: give kValue a real value-only path —
skip all Jacobian state / chain rule / per-endpoint IFT dtheta,dP / dP at the
angular nodes; compute F0 always, F_half only when u != 0 — so production
end-to-end does the right amount of work.  NOT a bid to hit the 2x gate
(structurally unreachable while D14 is in the epoch — §14 / decision-20).

INTERPRETATION
--------------
* The value lane is a REAL production win: ~1.1-1.25x end-to-end on the
  method-6 value path, with bit-identical mu and 0 status changes.  This is
  "make production end-to-end do the right amount of work" (message 29) —
  the ~1 ms/epoch of wasted Jacobian assembly (§29) is now largely recovered.
* It does NOT reach 2x, and cannot: the value lane only removes the Jacobian
  portion of the radial pass (~14% of the epoch, §14) plus — for u=0 — the
  F_half angular sweep.  D14 / classify_cells (~55-74% of the epoch) is
  untouched and shared.  §14 predicted ~1.3x isolated; measured 1.16-1.29x.
* holo method 6 is still ~4x slower than calibrated inverse-ray-polar on the
  cold value path (polar p50 ~277 us vs holo p50 ~1190 us); its production
  value on this path remains ACCURACY (~100x better median rel-err vs VBM at
  n_r=64), now delivered at ~1.1-1.25x less cost than before.
