3. THE rho-DERIVATIVE CANCELLATION GATE  (why 48 % of epochs re-run per-node)
--------------------------------------------------------------------------------

epoch grad_mu[2] = (dN/D) - 2 mu/rho, and

  dN/D - 2 mu/rho
     = { (1-u)(dF0_rho - 2 F0/rho) + u(dF_half_rho - 2 F_half/rho) } / D

so the cancellation lives (u-independently) inside  dF0_rho - 2 F0/rho  and
dF_half_rho - 2 F_half/rho.  For small rho both halves of each difference reach
1e3 .. 1e8 in magnitude and cancel to O(1e-2).  The incumbent GC64 radial pass
keeps F0 / dF0_rho to ~1e-9 relative and survives; the RK4 ODE transport only
reaches ~1e-5 .. 1e-6 relative, and the difference is then O(1) wrong (on the
worst cases sign-wrong).

  rho_cancel_kappa = max over {F0, F_half} of
       (|d_rho| + |2 F/rho|) / max(|d_rho - 2 F/rho|, 1e-300)

Calibration (ode_probe, 108 cases -- kappa vs |grad_mu[rho] V3-vs-V0|):
  kappa  > ~2e4     ODE sign-wrong / O(1) error   (rand026 1.3e5, rand008 1.6e8,
                                                   rand007 1.8e6, rand021 2.2e6)
  kappa  3e3 .. 2e4  ODE error 0.05 .. 0.26        (rand020 3e3, rand030 1e4,
                                                   extreme-q-lo 2e4, rand022 1.3e4)
  kappa  1e3 .. 3e3  ODE error 0.02 .. 0.05, BUT the ODE result is closer to a
                     high-n_r reference than the incumbent GC64 (see below)
  kappa  < 1e3       ODE and incumbent agree to < ~1e-2

Gate: used_ode && rho_cancel_kappa > kOdeRhoCancelMax (2.5e3)
   -> discard the ODE pass, re-run flux_jacobian_integrate with allow_ode=false
      (true fail-closed to the per-node incumbent -- "correctness fallback
      として残す").

Effect on the 108-case sweep (ode_probe / test_holonomic_ode):
                              before gate     after gate
  worst grad vec-rel (V3-V0)   0.395           2.55e-3
  worst grad rel     (V3-V0)   1.664           4.49e-2   (rand004, see note)
  worst |dmu/mu|               6.11e-5         6.11e-5   (unchanged; value fine)
  status changes vs V0         0 / 108         0 / 108
  epochs gated                 --              52 / 108

NOTE on the residual 4.49e-2 (rand004, kappa ~1.05e3, NOT gated):
  gcmp vs an n_r=512 reference --
    rand004 u=0.5: V0 (GC64) 4.272e-2 | V3 (ODE) 4.080e-2 | Ref512 4.136e-2
      -> V0-Ref +1.36e-3   V3-Ref -5.58e-4   (V3 is 2.4x closer to truth)
    rand036 u=0.5: V0 8.784e-1 | V3 8.656e-1 | Ref512 8.693e-1
      -> V0-Ref +9.12e-3   V3-Ref -3.71e-3   (V3 is 2.5x closer)
    rand032 u=0.5: V0 7.061e-1 | V3 6.938e-1 | Ref512 6.974e-1
      -> V0-Ref +8.77e-3   V3-Ref -3.57e-3   (V3 is 2.5x closer)
  i.e. the residual "worst grad rel" is a V3-vs-V0 disagreement in which V3 is
  the more accurate of the two -- lowering kOdeRhoCancelMax would REJECT the
  better answer.  The incumbent GC64 rho-derivative is itself ~1 % wrong on

6. INTERPRETATION
--------------------------------------------------------------------------------

* The full coupled-state ODE transport is IMPLEMENTED and CORRECT: mu parity
  ~1e-4, grad parity within the cancellation gate, audited as a true full-ODE
  path (0 angular-sweep nodes, 0 per-node quartic solves on the 230 adopted
  cells), 0 status changes.

* It is SLOWER than the direct solver, not faster -- 1.94x on the value+Jac
  whole epoch, 2.30x on the isolated radial pass, 1.13x value-only; never
  faster on any case; tails worse (jac p99 2.44x slower).  The cost driver
  is visible in the audit: 337 900 K-rule 16-node GC2 evaluations across 230
  cells (~1470 per cell), because v.K is re-evaluated at every RK4 stage
  (78 160 steps / 230 cells ~= 340 steps/cell x 4 stages).  The direct path
  does ~64 radial nodes x one 64-node angular sweep (~4 100 integrand
  evals/cell).  The ODE march does ~5-6x MORE flux-integrand work.

* This is consistent with the spike (c) verdict (memo §28): the K-rule is the
  UNIVERSAL transport but "jet is NOT more general ... speed-only"; the
  regime-2 flux-priority jet (decay_rho >= 6 -> replace the per-substep
  16-node K-rule sum with a seeded Taylor germ) was DEFERRED.  212 of the 298
  routed cells are regime-2 territory but currently all take the K-rule.  The
  1.47x epoch ceiling assumed the jet.

* The ~340 RK4 steps/cell is dominated by the adaptive v-clamp
  (kOdeVStepFrac = 0.10) crawling from v ~ 1e-3 down to kOdeVWork = 1e-9 before
  handing off to the u-sub tail.  Raising kOdeVWork (hand off to the tail
  earlier) is the obvious first speed lever -- untested, needs its own accuracy
  pass.

* 48% of epochs on this stress set trip the rho-cancellation gate and pay
  BOTH an ODE pass and a per-node pass.  The bench_cases.tsv set is
  deliberately extreme (many tiny-rho / wide / extreme-q); this is an upper
  bound on the gate rate, not a production estimate.

RECOMMENDATION
  Keep HOLO_ODE_TRANSPORT OFF by default.  It is (1) a correctness / A/B
  reference for the coupled-state transport and (2) the substrate for the
  regime-2 jet.  The shipped speed levers stay V1 ((m,v)-only, in the .so) and
  V2 (semi-holonomic v.K, isolated build).  Whether to build the regime-2 jet
  is a user call -- it is the only path to the 1.47x ceiling for fold-adjacent
  arcs, and it is "speed-only" (K-rule already gives the correct number).

TASK (user, 2026-09-09 -- "regime-2 flux-priority jet を C++ 実装 に GO"):

  across 230 cells) as the V3 cost driver.  Spike (c)/memo Sec.28 deferred the

WHAT WAS BUILT  (holonomic_ode_transport.hpp)
  - route_regimes now reports jet_eligible (regime 2 = dist_fold >= 2H).
  - ode_jet_build: per eligible cell, 9 Chebyshev-Gauss seed nodes over
    anchor +/- 0.85 H; at each node a single (m,v) sub-march + 1 K-rule eval of
    [v*K, d(v*K)/dp_j (x5)]; 9x9 Chebyshev-Vandermonde solve -> per-column
    coefficient-decay rho (slope of log|c_k| over k=2..6, k=1 skipped -- parity

    anchor (well-conditioned: anchor == seed-window centre).

    (= H), the F_half / dF_half_i accumulators are fed by jet_eval (Horner,
    degree 6) instead of v_times_K_jac / v_times_K.  The (m,v) march, dm/dp,
    dv/dp IFT algebra are UNCHANGED -- the jet only removes the K-rule call.
  - A regime-2 cell that still reaches a v-work fold edge mid-march (the linear
    dist_fold estimate is optimistic) is NOT failed: the germ covers

  - New env knobs (isolated build only): HOLO_ODE_JET_DECAY (rho gate override),

INTERPRETATION -- why -46 % K-rule only bought +19 % on the ratio

    removes the K-rule CALL at each stage but the stage still runs the full
    (m,v) transport: root_pair_dR Newton, the E/O Jacobian, the dm/dp + dv/dp
    IFT solve.  The K-rule was ~30-40 % of a stage; the rest stays.  So the
    step-count crawl (adaptive v-clamp from v~1e-3 to kOdeVWork=1e-9 before the
    u-sub tail hand-off) is now the dominant term, not the K-rule.
  * 52 / 108 epochs still trip the rho-cancellation gate and pay BOTH an ODE
    pass and a full per-node pass.
  * Only 130 / 196 eligible cells take the jet (60 demoted by the 6-column decay
    gate).  Loosening the gate risks the rand004/rand013 param-derivative edge
    error (already 4.5e-2 vs the 5e-2 tolerance).

  necessary for the 1.47x ceiling but NOT sufficient on its own.  The next
  lever is structural -- either raise kOdeVWork (hand off to the u-sub tail
  earlier, cutting the step-count crawl) or the "aggressive" regime-2 form
  (analytic F_half integral of the degree-6 packet + a fixed low-order GL rule
  for F0 -> drop the RK4 march on regime-2 cells entirely).  Both are the
  user's call; neither is started.
