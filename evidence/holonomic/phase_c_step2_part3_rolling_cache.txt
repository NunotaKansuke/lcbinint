3. SPEED -- the finding: no measurable whole-trajectory win on the VALUE path
--------------------------------------------------------------------------------
3a. Isolated full-Jacobian path (bench_holonomic_trajectory, best-of-30):
        V0 cold          median 1.2229 ms   p90 1.9567  p99 3.3466
        V1 L2 warm-D14   median 1.1651 ms   p90 1.8873  p99 3.0980
        V1 steady speedup vs V0 median : 1.05x   (was 1.08x at S21;
        B1 compensated double-double D14 polish, shipped since S19, has cut the
        cold D14 solve cost that S21's warm-seed was recovering -> the L2 gain
        has eroded to ~1.05x, right at this host's load-10..14 noise floor.)

3b. End-to-end production value path (_evaluate_preplanned_xy, method 6,
    RequestedOutput::kValue -- note the Phase D value lane is NOT built, so
    kValue still runs the full fused epoch_jacobian_prepared pass):

    trajectory s=0.9 q=0.2 rho=0.008 u=0.6, single 6-cusp caustic
      N=400  XR=0.85  reps=15   (wide pass, drift 0.71 rho/step near centre)
        whole-trajectory  polar 255.5 ms / holo C 733.5 / holo W 742.8
        speedup  t_C / t_W = 0.988x     (prepared marginally SLOWER)
        rel-err vs VBM median : polar 2.45e-5 / holo C,W 1.98e-7  (~124x better)
      N=1500 XR=0.20  reps=6    (caustic zoom, drift 0.033 rho/step)
        whole-trajectory  polar 1713 ms / holo C 3091 / holo W 3152
        speedup  t_C / t_W = 0.981x
        rel-err vs VBM median : polar 7.86e-6 / holo C,W 2.83e-5
        per-epoch us p50 : polar 972 / holo C 2207 / holo W 2231

    Why the isolated 1.05x does not survive to the E2E path: per-epoch wall
    clock is ~2.2 ms E2E vs ~1.2 ms isolated kernel.  The extra ~1 ms/epoch is
    pybind marshalling + com-frame transform + linear-LD blend + the
    LightCurve per-epoch loop, none of which the rolling cache touches.  That
    halves the kernel's share of the epoch, so a 1.05x kernel gain becomes
    ~1.02x E2E -- indistinguishable from noise at load 10..14.

3c. Holo (method 6) vs calibrated inverse_ray_polar (method 3), whole track:
        wide pass    : t_polar / t_holo = 0.35x   (holo ~2.9x slower)
        caustic zoom : t_polar / t_holo = 0.55x   (holo ~1.8x slower)
    Polar at the per-epoch calibrated low resolution (_binary_resolution_hint)
    is genuinely cheap; holo pays the full D14 classify_cells every epoch
    (~55% of the epoch, shared, untouched by the radial-pass optimisation).

4. INTERPRETATION
--------------------------------------------------------------------------------
* Part 3's rolling cache is now a real production capability: exact-parity,
  fail-closed, 0 status changes, incumbent bit-identical.  The structural
  enablement is done.
* It does NOT deliver a wall-clock win on the current production path, because:
    - the S29 1.183x radial-pass win lives on the FULL-Jacobian flux pass and
      is gated behind HOLO_HOLONOMIC_TRANSPORT (still OFF); the shipped .so
      carries only the (m,v) 1.028x;
    - the S21 ~1.08x D14-reuse win that Part 3 threads has eroded to ~1.05x
      (isolated) / ~noise (E2E) because B1 already cut the cold D14 solve;
    - the production value path is kValue but the Phase D value lane does not
      exist yet, so it pays the whole fused Jacobian pass and then discards it.
* Holo's demonstrated production value on this path is ACCURACY, not speed:
  ~100-120x better median rel-err than calibrated polar at a fixed n_r=64, and
  exact reproducibility across the rolling cache.
* This is the "real comparison" the user asked for (message 27: "Part 3 が
  本当の比較になる").  Verdict: on the production value path, holonomic +
  full reuse ~= the direct solver in wall-clock, wins ~100x on accuracy,
  exact parity, 0 status changes; it is 1.8-2.9x slower than calibrated
  inverse-ray-polar end-to-end.
