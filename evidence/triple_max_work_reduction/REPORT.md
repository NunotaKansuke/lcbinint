# Triple通常APIの仕事量削減と最終比較

## 採用した変更

- 同時求根のAberth反発項で、根の組を一度だけ評価して正負を配る。係数絶対値も根ごとに再計算しない。収束後の残差・Vieta完全性検査、失敗時の再求根は維持。通常範囲の逆数だけ軽量化し、一般のNewton除算は標準のスケール付き複素除算を維持する。
- 通常支持領域の境界イベント探索を256 boxで打ち切らず、同じ探索途中データで1024まで継続できるようにした。少しの追加探索で高価な全域fallbackを回避する。全体のevent_budgetは引き続き尊重する。近い光源では前の境界イベントから初期角度分割を回転し、全周の証明をやり直す。古い証明を流用する処理ではない。
- 角度方向の曲率を既存の実成分演算で計算する。LDの局所quad fallbackでは、同一半径のGradientRay/ValueRayを必要時に一度構築し、端点・追加サンプルで共有する。微分方向ごとのquad除算を共通の随伴ベクトルにまとめる。
- 角度多項式で繰り返していた小さな二項係数を正確な整数表にした。値・微分の共通処理に適用。
- 要求精度、値によるrefinement、局所quadへのfallback条件を維持。微分誤差によるrefinementは追加していない。値のみ経路で微分用quadキャッシュは構築しない。

## 比較条件

Eight independent persistent engine processes, CPU0, one thread, serial rotated/reversed requests. 65 uniformly spaced epochs. Constructor+first API call cold; two warmups, eight measured warm calls; four geometry-change calls alternating s*(1.0001/1.0002). Thread CPU ms inside worker exclude IPC/imports/serialization. Ordinary default native LightCurve, no backend flag. VBM TripleLightCurve SinglePoly/MultiPoly/NoPoly, Tol=0/RelTol=request, linear LD; Tol=0 disables its corrquad<Tol point shortcut, this is the requested relative-only contract, not VBM defaults. point_base is an intentionally point-only native mode=0 ablation, not an equivalent finite-source competitor or stage timer. No builds, references or profiling concurrent with timing. CPU frequency/external load uncontrolled.

変更前は今回の作業開始時のdirty checkoutから保存したnative package。HEADだけの比較ではない。最終source/DSOと変更前DSOのhashはprovenance.json、開始時差分はbefore.diffに保存した。中間の一般複素除算簡略化案は極端な値で中間積のunderflowがありうるため不採用とし、general-division-trial/に隔離した。最終表には含めない。

## 精度と範囲

- C++30テスト、API回帰27テスト通過。点光源の独立診断1792点で全status=0、VBM3方式との最大相対差5.3e-10。
- 追加の旧point-source/safetyテストは18件通過・9件失敗。保存した変更前packageでも同じ9件が失敗し、新規失敗は0。古いinverse-ray既定値または削除済みwrapper属性を期待するテストであり、この作業では書き換えていない。詳細はlegacy-test-comparison.json。
- 別の7配置・2半径・2LD・2要求精度・両native経路の1008点出力を、VBM SP/MP relative1e-7・absolute0と比較。全status=0、要求誤差超過0。matrix.jsonに保存。
- 上表48条件・両モードで6240 epoch出力。保存した初回・warm・形状更新を含む全呼出しの非ゼロstatus=0、無効微分フラグ=0、値/微分の経路不一致=0。
- 前回独立に計算した厳しいVBM SP/MP参照を、同一cases.jsonを確認して再利用。364点、両精度・両経路で1456値を照合し、要求相対誤差超過=0、最大相対差=0.000375。全6240点を厳しい参照で照合した意味ではない。
- GradientRayの全8方向は一般のpromoted方程式とのC++比較を通過。微分のbefore/after差はsummary.jsonに保存。gradient_validは精度保証ではない。新たな微分専用の精度契約は導入していない。
- 静的・水平軌道の限定検証。全レンズ配置、視差、軌道運動、全微分方向の精度を認定したものではない。

再現: build-safe-reciprocal.log、ctest-safe-reciprocal.log、regression-safe-reciprocal.log、point_check.py、validate_matrix.py、audit.py、summarize.py。全raw時間・値・解析微分・経路はrows/*.json。
