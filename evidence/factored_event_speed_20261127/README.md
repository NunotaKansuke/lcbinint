# Factored triple event and angular-root timing

Measured on rogue1 using the working tree of experiment/algebraic_boundary at 7038d6c2. The comparison starts from the previous stationary-diameter optimization. Native module SHA-256 before and after was `cff43bf4bdee18df05c274feb06307f6522028ba32738dd358c45fbef7539760` and `9d1a9391092d57b16ab7d7fefa97d8e537de23667486364415f89b1fdde79b97`, respectively. Each driver checked its loaded extension path.

The public benchmark used ../eight_mode_speed_20261127/bench.py with offsets 0 and 1, 16 fixtures per lens, four two-epoch calls per fixture, absolute tolerance zero and relative tolerance 1e-4. CPU 2, one thread, three paired runs with reversed order on run 2. timing.tsv gives thread CPU milliseconds per epoch and ratios of medians. The driver calls values before gradients and can warm the support cache. Compare timings within each mode.

The 56-query event probe retained all counts and completion flags with 45,011 physical search boxes before and after. The accepted code keeps the factored radial polynomial for event enclosures, propagates just its first radial derivative while forming coefficients, and reuses the angular basis in the original interval arithmetic. Promoted physical proofs reuse their full-box Jacobian. Other savings come from the midpoint Bernstein reduction and sign reuse across monotone angular segments.

Across all 1,768 archived triple inputs at their central epoch, value and gradient calls completed (3,536 evaluations, 1,091 integrated epochs per mode). The maximum change in magnification relative to the before build was 7.6e-12. The maximum per-epoch infinity norm of the gradient change divided by max(1, before gradient infinity norm) was 1.11e-08. Status, validity, integral support and route flags matched. For the 32 epoch/profile inputs with strict VBM MultiPoly comparisons, maximum relative value difference was 3.96e-05 (Tol=1e-8, RelTol=1e-6).

Fixture 0254 has two small companion masses and limb coefficient 1. At its central epoch a discarded expanded-coefficient candidate shifted the q2 derivative from 0.07547 to 0.11660. Single-change isolation traced this to contracting and publishing roots using the expanded binary64 coefficients. VBM MultiPoly central differences with RelTol=1e-7, 1e-8 and 1e-9 and h/q2=1/4, 1/8 and 1/16 spanned 0.0711508 to 0.0711518. The accepted loose mesh returns 0.07547. This is a regression guard for the mass derivative, not component-by-component relative accuracy at the value tolerance.

The separate value-only timing of original cases 568 and 889 (six epochs combined, Tol=RelTol=1e-4, five warm calls per curve, medians across three runs) was 24.51 ms versus 6.97 ms for uniform sources and 23.62 ms versus 109.36 ms for linear limb coefficient 0.5 (experiment versus VBM).

All five selected C++ tests passed. The full triple Python regression files produced 259 passes and the same nine failures in test_triple_lens_point_source.py on both builds. This includes the new mass-gradient regression. Raw outputs, commands, profiles, rejected trials and both failure lists are in build-accuracy-20261127/disk-cover-speed in the parent checkout.
